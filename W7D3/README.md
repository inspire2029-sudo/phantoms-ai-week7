# W7D3 — RAG Pipeline

## الهدف

ربط قاعدة المتجهات التي بُنيت في W7D1 واختُبرت في W7D2 بنموذج لغوي، بحيث يمر السؤال بمراحل الاسترجاع ثم توليد إجابة مقيدة بالدليل الموجود في التقرير. المطلوب ليس مجرد إجابة لغوية؛ المطلوب إظهار المقاطع المسترجعة ومصادرها، ومقارنة الإجابة مع وبدون RAG، ومراجعة الحالات التي لا يتوفر لها دليل.

## مصدر البيانات والإعدادات

| العنصر | الإعداد |
|---|---|
| المستند | `data/source_document.pdf` — تقرير SGDS SWARM Civil Edition |
| عدد صفحات المصدر المتوقع | 53 |
| قاعدة البيانات | قاعدة W7D2 الموجودة مسبقًا |
| مسار Chroma الافتراضي | `chroma_db/w7d2_chunking` |
| اسم Collection | `large_1600_250` |
| عدد المقاطع المتوقع | 62 |
| إعداد التقسيم | 1600 حرف، وتداخل 250 حرف |
| نموذج التضمين | `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` |
| الاسترجاع | Top 3 |
| النموذج اللغوي الافتراضي | Ollama — `qwen2.5:3b` |
| مهلة طلب النموذج | 600 ثانية افتراضيًا |

**مهم:** W7D3 يفتح قاعدة W7D2 الأصلية ولا يعيد إنشاءها. لو قاعدة W7D2 أو الـ Collection مش موجودة، البرنامج يتوقف برسالة واضحة بدل ما ينشئ قاعدة بديلة ويعرضها بالخطأ على إنها نفس قاعدة اليوم الثاني.

## دورة العمل

1. **Query Embedding:** تحويل السؤال إلى متجه باستخدام نفس نموذج التضمين المستخدم في W7D2.
2. **Retrieval:** البحث في Collection `large_1600_250` واسترجاع أقرب ثلاثة مقاطع.
3. **Context Construction:** تجهيز نص المقاطع مع اسم المصدر ورقم الصفحة من Metadata.
4. **Grounded Generation:** إرسال السؤال والسياق إلى Ollama مع تعليمات تمنع استخدام المعرفة العامة أو اختراع أرقام ومصادر.
5. **Source Traceability:** حفظ المقاطع المسترجعة والمسافات والصفحات بجانب الإجابة.
6. **No-RAG Baseline:** تشغيل Q1 وQ9 وQ10 من غير سياق مسترجع للمقارنة.
7. **Checkpointing:** حفظ JSON وCSV بعد كل سؤال حتى لا تضيع النتائج المكتملة عند حدوث Timeout أو توقف.

Q9 وQ10 لا يُصنّفان تلقائيًا على أنهما غياب للمعلومة لمجرد أن Top 3 لم يُرجعها. عدم العثور في أول ثلاثة مقاطع يعني أن الاسترجاع لم يعرض الدليل؛ ولا يثبت وحده أن التقرير كله يخلو منه. يجب مراجعة المستند كاملًا قبل اعتماد حكم الغياب.

## Grounding ورفض التخمين

الـ System Prompt يطلب من النموذج استخدام الـ Context فقط. إذا كان الدليل غير موجود أو غير كافٍ، يُطلب منه الرد حرفيًا:

`مش موجود في المستند`

وجود صفحة مصدر بجانب الإجابة لا يثبت وحده صحتها؛ إذ تُقاس مطابقة الإجابة بمقارنة الادعاءات بنصوص المقاطع المسترجعة والمستند الأصلي. البرنامج يسجل حالة تنفيذ أولية فقط:

- `ABSTAINED`: النموذج استخدم عبارة الامتناع.
- `GENERATED_REQUIRES_REVIEW`: تم توليد إجابة وتحتاج مراجعة بشرية.
- `ERROR`: فشل طلب النموذج أو حدث خطأ أثناء السؤال.

لا يعتبر البرنامج أي إجابة صحيحة تلقائيًا، ولا يحوّل غياب الدليل في Top 3 إلى إثبات بأن المعلومة غير موجودة في التقرير.

## المتطلبات والتشغيل على Fedora

من جذر المستودع:

```bash
cd ~/Projects/phantoms-ai-week7
source .venv/bin/activate
python -m pip install -r requirements.txt
```

تأكدي من وجود ملف المصدر:

```bash
ls -lh data/source_document.pdf
```

تأكدي من وجود قاعدة W7D2:

```bash
ls -la chroma_db/w7d2_chunking
```

شغّلي Ollama في نافذة Terminal مستقلة إذا لم يكن يعمل بالفعل:

```bash
ollama serve
```

وفي نافذة ثانية تأكدي من وجود النموذج:

```bash
ollama list
```

لو مش موجود:

```bash
ollama pull qwen2.5:3b
```

شغّلي الـ Pipeline مع حفظ سجل الطرفية:

```bash
python W7D3/W7D3_RAG_Pipeline.py 2>&1 | tee W7D3_run.log
```

لو حصل Timeout، عالجي سبب بطء Ollama ثم أعيدي نفس الأمر. النتائج المكتملة محفوظة كنقاط استكمال، والأسئلة التي حالتها `ERROR` يعاد تنفيذها عند التشغيل التالي.

### متغيرات اختيارية

لو قاعدة W7D2 في مكان مختلف، حددي المسار واسم الـ Collection الحقيقيين:

```bash
export CHROMA_PATH="/absolute/path/to/w7d2_chunking"
export CHROMA_COLLECTION="large_1600_250"
```

يمكن تغيير مهلة Ollama أو عدد النتائج عند الحاجة:

```bash
export OLLAMA_TIMEOUT=900
export RAG_TOP_K=3
```

لا تغيّري Top K في منتصف المقارنة إلا إذا وثّقتِ الإعداد الجديد بوضوح.

تُحدّث ملفات النتائج بعد كل سؤال. لا تضعي نتائج متوقعة أو إجابات مكتوبة يدويًا في خانة النتائج الفعلية.

## تقييم النتائج

يعتمد التقييم النهائي على مقارنة كل إجابة بالـ Context والـ PDF الأصلي، ويُسجل الحكم التحليلي وفق التصنيفات التالية:

| التصنيف | معناه |
|---|---|
| CORRECT | كل الادعاءات الأساسية مدعومة بالدليل |
| PARTIAL | بعض الإجابة مدعوم وبعضها ناقص |
| INCORRECT | الإجابة تناقض المصدر أو تتضمن ادعاءات غير مدعومة |
| ABSTAINED_CORRECTLY | امتنع لأن الدليل غير موجود بعد مراجعة المصدر |
| ABSTAINED_UNNECESSARILY | امتنع رغم وجود الدليل في المصدر |
| RETRIEVAL_FAILURE | الدليل موجود في المصدر لكنه لم يظهر في المقاطع المسترجعة |
| GENERATION_FAILURE | الدليل موجود في الـ Context لكن النموذج لم يستخدمه بشكل صحيح |

هذه التصنيفات للمراجعة البشرية؛ حالة البرنامج الأولية ليست حكمًا نهائيًا على الصحة.

## تحليل حالة الفشل — Q4

يُستخدم Q4 لتحديد موضع الخلل المحتمل دون افتراض مسبق أن المشكلة من الاسترجاع أو التوليد:

- **Retrieval failure:** الفقرة المطلوبة موجودة في التقرير لكنها غير موجودة في Top 3.
- **Generation failure:** الـ Context يحتوي على الدليل المطلوب لكن الإجابة أسقطته أو حرّفته أو أضافت ادعاءً غير موجود.
- **Mixed failure:** الاسترجاع جزئي والإجابة نفسها غير مكتملة.
- **No demonstrated failure:** المقاطع والإجابة كلاهما صحيحان؛ لا تسجلي فشلًا لمجرد أن السؤال اختير للتحليل.

يعتمد التشخيص على نصوص Top 3 المسجلة في JSON ومقارنتها بصفحات المصدر. ويمكن تنفيذ تجربة إضافية بـ Top 5 أو إعادة صياغة السؤال باعتبارها تجربة مستقلة عن نتائج Top 3 الأساسية.

## المقارنة بدون RAG

يُشغّل البرنامج Q1 وQ9 وQ10 مرة أخرى من غير Context. تُقارن إجابات النموذج في الحالتين من حيث:

- الالتزام بالمعلومات الواردة في التقرير.
- اختراع الأرقام أو تفاصيل الاختبار.
- القدرة على الامتناع عند عدم التأكد.
- الفرق بين إجابة عامة صحيحة وإجابة مثبتة من المستند.

لا تُعتبر إجابة النموذج بدون RAG دليلًا على محتوى التقرير.

يتضمن مجلد `evidence/` لقطات توضح العناصر التالية:

1. إظهار نسخة Python والمكتبات والنموذج المحلي.

3. مثال لاسترجاع Top 3 مع أرقام الصفحات والمسافات.
4. مثال لإجابة مدعومة ومصادرها.
5. مثال Q9 أو Q10 ونتيجة الامتناع أو ما كشفته مراجعة المصدر.
6. ملخص التشغيل ووجود ملفي JSON وCSV.

## حدود التجربة

- التجربة على مستند واحد ومجموعة من عشرة أسئلة.
- Top 3 اختيار تجريبي وليس ضمانًا للدقة.
- المسافة الأقل لا تعني بالضرورة أن المقطع يجيب عن السؤال.
- المصادر والصفحات تساعد على التتبع لكنها لا تغني عن مراجعة الدليل.
- نتائج النموذج مرتبطة بإصداره وإعداداته وموارد الجهاز.
- صحة الإجابات النهائية تحتاج مراجعة بشرية مقابل التقرير.
