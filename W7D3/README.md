# W7D3 — RAG Pipeline

## الهدف

توصيل الـ Vector Database بالـ LLM في Pipeline واحدة تبدأ بالسؤال وتنتهي بإجابة مرتبطة بمصدرها مع الامتناع عن التخمين لما المعلومة مش موجودة.

## إعداد التجربة

- المستند: `data/source_document.pdf` — تقرير SGDS SWARM Civil Edition
- إعداد D2 المختار: Large — 1600 character مع Overlap 250
- Embedding model: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`
- Retrieval: Top 3
- Vector DB: ChromaDB
- LLM: Ollama — الافتراضي `qwen2.5:3b`

البرنامج بيحاول يفتح Collection موجودة من D2. لو مش لاقيها بيعيد بناء نفس إعداد Large من ملف الـ PDF. تقدري تحددي مسار قاعدة البيانات واسم الـ Collection بمتغيرات البيئة `CHROMA_PATH` و`CHROMA_COLLECTION`.

## مراحل RAG

1. **Indexing** — قراءة التقرير وتقسيمه إلى Chunks وتحويلها إلى Embeddings وتخزينها مع اسم الملف ورقم الصفحة في Metadata
2. **Retrieval** — تحويل السؤال إلى Embedding واسترجاع أقرب 3 Chunks من ChromaDB
3. **Generation** — وضع السؤال والـ Context داخل Prompt وإرسالهم إلى LLM مع تعليمات تمنع استخدام معلومات خارج المستند

## ليه Top 3

قطعة واحدة ممكن تكون ناقصة بينما عدد كبير زي 20 ممكن يدخل سياق بعيد ويشتت الموديل. Top 3 نقطة بداية متوازنة ومثبتة في إعداد التجربة، لكنها مش قيمة مثالية لكل المستندات.

## Grounding ورفض الإجابة

الـ System Prompt بيطلب من النموذج الاعتماد على الـ Context فقط. لو الدليل غير موجود أو غير كافٍ لازم يرد حرفيًا: **مش موجود في المستند**. البرنامج نفسه بيطبع اسم الملف ورقم الصفحة من Metadata؛ مش بيعتمد على الموديل في اختراع المصدر.

## الأسئلة العشرة

الأسئلة دي هي مجموعة الاختبار المستخدمة في الكود. الأسئلة Q9 وQ10 مقصود إن بياناتها الرقمية مش مذكورة في التقرير.

| ID | السؤال | مرجع التقييم |
|---|---|---|
| Q1 | ما الدور الذي تمثله كل طائرة داخل منظومة SGDS SWARM؟ | الطائرة عقدة استشعار ومعالجة وتنفيذ محلي |
| Q2 | ما الطبقات الوظيفية العشر وما الطبقتان العرضيتان؟ | عشر طبقات وظيفية وطبقتا Cybersecurity وSafety / Reliability |
| Q3 | لماذا لا يعتمد التقرير على عتبة بطارية ثابتة وما مدخلات تقدير زمن المهمة الآمن؟ | استهلاك متغير وطاقة متبقية وطاقة عودة واحتياطي سلامة |
| Q4 | ما المقاييس التشغيلية التي يوصي التقرير بتسجيلها بجانب mAP؟ | False Alarms per Operational Hour وLatency وFPS وWatt per Inference وThermal Throttling |
| Q5 | كيف يتعامل النظام مع تراجع إصدار نموذج وكيف يراقب تغير البيانات؟ | Rollback ومؤشرات Data Drift |
| Q6 | ما إجراءات إدارة مفاتيح وحدات الأسطول وتأمين تحديثات البرامج؟ | إنشاء وتوزيع وتخزين وتدوير وإلغاء المفاتيح والتحقق من التوقيع |
| Q7 | ما المبدأ الذي يحكم تصرف الطائرة عند فقدان اتصال الشبكة؟ | منطق سلامة محلي لا يعتمد على الخادم |
| Q8 | ما تسليمات فريق الذكاء الاصطناعي بخلاف model.pt؟ | Dataset وTraining وEvaluation وArtifacts وBenchmark وInference وEvent API وModel Card وغيرها |
| Q9 | ما قيمة mAP الفعلية في اختبار ميداني موثق على Jetson؟ | غير مذكورة |
| Q10 | كم رحلة اختبار مكتملة وما متوسط زمن الطيران المقاس؟ | غير مذكور |

> أرقام الصفحات والمصادر الفعلية بتتحدد من Metadata اللي بيرجعها Chroma وقت التشغيل. لازم مراجعة نص الـ Chunks قبل اعتماد التقييم.

## طريقة التشغيل السريعة على Fedora

من جذر المشروع:

```bash
cd ~/Projects/phantoms-ai-week7
source .venv/bin/activate
```

لو المتطلبات مش متثبتة:

```bash
pip install chromadb fastembed pypdf requests
```

حطي نسخة التقرير في `data/source_document.pdf` لو مش موجودة بالفعل. بعد كده شغلي Ollama:

```bash
ollama serve
```

في Terminal تاني:

```bash
ollama pull qwen2.5:3b
python W7D3/W7D3_RAG_Pipeline.py
```

لو Ollama شغال بالفعل مش محتاجة تشغلي `ollama serve` مرة تانية.

### اختيار مسار Chroma

البرنامج بيدور افتراضيًا في `chroma_db` ثم `chroma_db/w7d2_chunking` وبيحاول يفتح Collection باسم `large_1600_250` ثم أسماء Large الشائعة. لو مسار D2 عندك مختلف حدديه قبل التشغيل:

```bash
export CHROMA_PATH="/full/path/to/your/d2/chroma_db"
export CHROMA_COLLECTION="اسم_collection_الفعلي"
```

## مقارنة بدون RAG

الكود بيشغل Q1 وQ9 وQ10 مباشرة مع نفس نموذج Ollama لكن من غير Context. قارني النتائج مع RAG: هل الإجابة مرتبطة بالمستند؟ وهل النموذج اخترع أرقامًا للأسئلة غير الموجودة؟

## تحليل حالة الفشل

استخدمي Q4 كحالة للتحليل بعد التشغيل:

- **Retrieval failure:** لو الـ Top 3 ما جابوش الفقرة أو جابوا جزء ناقص. جرّبي Top 5 أو Chunking يحافظ على الفقرة أو Reranking.
- **Generation failure:** لو الـ Context فيه المقاييس كاملة لكن الموديل نسي بعضها أو أضاف معلومة. حسّني صياغة الـ Prompt واطلبي إخراجًا منظمًا.
- **Mixed failure:** لو الدليل المسترجع جزئي والإجابة كمان فيها قصور.

ما تختاريش سبب الفشل قبل ما تقري الـ Chunks الفعلية في ملف النتائج.

## حدود التجربة

التجربة على مستند واحد وعشرة أسئلة فقط. Top 3 مش ضمان للدقة، والمسافة في Chroma مش مقياس لصحة الإجابة. وجود المصدر بيسهّل المراجعة لكنه لا يغني عن فحص الدليل نفسه.
